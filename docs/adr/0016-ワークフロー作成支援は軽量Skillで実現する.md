# ワークフロー作成支援は軽量Skillで実現する

ワークフロー作成は1回きりの生成タスクであり、tadoエンジン駆動のワークフロー（`workflow.ts`を持つ多段階ワークフロー）で実現すると、ワークフローを作るためにワークフローを走らせる循環と、親子セッション・状態管理の複雑化を招く。`tado-run` が汎用ランナーとして既に存在することからも、作成支援はLLMが直接 `workflow.ts` を生成する軽量Skill（`skills/tado-create-workflow/SKILL.md`）とし、エンジンは使わない。生成されたワークフローは `{TADO_HOME}/workflows/<workflow-id>/index.ts` へ単体配置し、`tado list --workflow --json` で列挙後 `tado init --workflow <id> --title "<title>"`（`--title` は 1-100文字で必須）で起動する。旧案の `resolveSkillsDir/<skill-name>/workflow.ts + SKILL.md` 2ファイル同居とパス起動 `tado init --workflow ./workflow.ts` は `{TADO_HOME}` 集約と `isPathLike → throw` の原則に反するため不採用。代替案のエンジン駆動型とCLIコード生成型は、決定論の過剰適用とプロンプト設計の文章生成ができない理由で却下した。
